# Standalone product strings

`mb/tools/branding_strings.py` derives three product-owned inputs from the pinned
Chromium checkout: Chrome's `chromium_strings.grd`, its settings GRDP, and
`components_chromium_strings.grd`. It does not edit the checkout or integrate
resources into the browser. It uses the validated `mb/branding.toml` manifest.

Generate the full production inputs:

```sh
python mb/tools/branding_strings.py
```

The default destination is `.build/generated/branding-strings`. `--manifest`,
`--source`, and `--out-dir` accept explicit paths. The source checkout HEAD must
match `mb/upstream-version.toml`. The receipt records that commit, the engine
version, manifest digest, and SHA-256 hashes of the source GRDs/GRDP, every
referenced XTB, and the resource-ID specification. Before writing any output,
the generator checks Git blob identities computed from those exact bytes against
the pinned commit using one batched, path-limited `git ls-tree` query. A modified
input is rejected even when checkout HEAD still matches the pin. The receipt
also records the verified Git blob IDs. Unrelated checkout files are not scanned
or certified. XTB paths remain external references, so this guarantee applies
when generating; keep the checkout inputs unchanged when subsequently running
GRIT (or regenerate to recheck them).

Generation preserves message ordering, conditional branches, attributes,
placeholder subtrees (including examples), meanings, and every production output
declaration. XML serialization can change quote/empty-element formatting without
changing that structure. The settings part stays adjacent to its generated GRD;
translation paths become absolute references into the pinned source tree.

Whole-word `Chromium` in ordinary message text and tails becomes the manifest's
full product name. `ChromiumOS` is not a whole-word match. The two exact identity
IDs, `IDS_PRODUCT_NAME` and `IDS_SHORT_PRODUCT_NAME`, use full and short names,
respectively. The auxiliary GRDP generated by `branding.py` is not appended.

Protected upstream attribution is explicit:

- `IDS_ABOUT_VERSION_COMPANY_NAME` and `IDS_ABOUT_VERSION_COPYRIGHT` are unchanged,
  as is any message whose ID contains `COPYRIGHT`.
- `IDS_ABOUT_CROS_VERSION_LICENSE` and
  `IDS_ABOUT_CROS_WITH_LINUX_VERSION_LICENSE` retain their upstream wording.
- `IDS_VERSION_UI_LICENSE`, `IDS_VERSION_UI_LICENSE_CHROMIUM`, and
  `IDS_VERSION_UI_LICENSE_OTHER` change only the leading distribution name.
  The Chromium project link text, link placeholders, and other software
  attribution stay unchanged.

Google-service references and translator descriptions/examples are not globally
rewritten. This is scoped derivation of these inputs, not a repository-wide name
replacement or a claim of complete browser branding.

Names are inserted into messages used in several formatting contexts. In
addition to the central manifest validator, this pipeline rejects `%`, braces,
`#`, apostrophe, `&`, angle brackets, and square brackets in full/short names.
These may change printf, ICU, mnemonic, markup, or GRIT substitution semantics;
one universal escaping rule would be incorrect. Errors identify the manifest
field. The current `mb` name is supported.

## Translations and resource IDs

No translated entries are fabricated or rewritten. Unchanged source messages
retain their XTB fingerprints and original translations. Changed source text
gets a new fingerprint; the upstream `fallback_to_english="true"` supplies the
new English text when a corresponding translation is absent. This produces
mixed-language UI until product translations are supplied. Reusing an old
fingerprint for changed wording would silently restore upstream branding and
must be avoided.

Numeric compiled resource IDs are separate from translation fingerprints. The
generated `first_ids.py` carries the pinned allocation for each generated GRD:
Chrome messages start at 800; component branded messages start at 7020. Keeping
the original message tree/order preserves actual resource IDs. The mapping's
`SRCDIR` is its own directory. GRIT takes this mapping with `-f` (there is no
`--first-id-file` option in the pinned CLI).

GRIT can compile the generated Chrome bundle directly:

```sh
GRIT_DISABLE_MULTIPROCESSING=1 TMPDIR="$PWD/.build/tmp" python \
  .build/chromium/src/tools/grit/grit.py \
  -i .build/generated/branding-strings/chromium_strings.grd build \
  -o .build/generated/branding-string-paks \
  -f .build/generated/branding-strings/first_ids.py -t linux \
  -D _is_chrome_for_testing_branded=false -D toolkit_views=true \
  -D use_titlecase=false -D enable_extensions=true \
  -D enable_extensions_core=true -D enable_pdf=true
```

Ensure `.build/tmp` exists before invoking that command. Substitute the component
GRD filename to compile its bundle. Integrated builds must supply their actual
GRIT feature definitions. Keep compiled paks outside the generator's managed
input directory. `--assert-file-list` may additionally specify a file containing
the complete absolute output paths, one per line; it asserts all outputs rather
than selecting a subset.

## Verification and output ownership

```sh
python mb/test/test_branding_strings.py
```

Tests invoke the pinned GRIT on separate baseline and derived inputs beneath
`.build/tmp`, with multiprocessing disabled. Only test copies reduce outputs to
the header and English/German paks; generated production inputs retain all
outputs. The tests compare actual resource-ID maps, inspect product names and
English fallback in paks, verify unchanged German translations, and check
placeholder, copyright, and license-link preservation. They also exercise
determinism and refusal of unsafe output paths. Missing pinned source skips the
suite rather than reporting a resource compilation success.

The generator accepts a new/empty directory or its own exact managed file set.
It refuses source-tree destinations, symlink paths, unexpected files, invalid
receipts, and edited managed files. Individual files are replaced atomically and
the receipt is written last. A process interruption can leave a deliberately
untrusted partial generation; inspect it and choose a fresh output directory.
Concurrent generation into one destination is unsupported. These are resource
pipeline checks, not a browser build, launch, or desktop-integration claim.
